# 前端开发规范
> 适用范围：`host`（壳应用）、`remote/*`（业务子应用）、`share/*`（共享模块）三类工程。
> 保证边界清晰、共享依赖稳定、代码风格统一、可独立开发独立部署。
---

## 一、技术栈基线

| 类别 | 选型 | 约束 |
|------|------|------|
| 语言 | TypeScript 5+ | ✅`strict: true`，❌ `// @ts-ignore`，需要时用 `// @ts-expect-error` |
| 框架 | React 19 | 函数组件 + Hooks，❌ class 组件 |
| 构建 | Vite 6 + `@module-federation/vite` | 各子包独立配置，不共享 `vite.config.ts` |
| UI | Ant Design 6 + `@ant-design/icons` | 统一走 AntD 主题变量 |
| 样式 | Tailwind CSS 4 + SCSS | 组件内布局优先 Tailwind，复杂样式 `.scss` |
| 路由 | React Router 6 | 开启 `v7_startTransition`、`v7_relativeSplatPath` |
| HTTP | Axios（`comm/request`） | ❌ 在业务代码中直接 `import axios`，统一走共享封装 |
| Node | ≥ 20.18.1 | 与 Vite 6 对齐 |

## 二、工程结构约定

### 2.1 仓库分层

```
web2/
├── host/         # 壳应用：路由、布局、子应用注册与鉴权
├── remote/*      # 业务子应用：仅通过 MF 暴露，❌ 相互直接 import
└── share/*       # 共享模块：comm 提供基础能力，data 提供数据分析领域共享能力
```

- `remote/*` ❌ 相互注册或消费业务 remotes；metric、board、report 的跨应用能力统一由 `data` 提供。
- `share/*` ❌ 依赖 `remote/*`。`comm` 提供请求、会话、主题等基础能力；`data` 可包含编辑器、查询控件和嵌入预览及其必要请求、状态和资源，只依赖 `comm`。
- `host` 不承载业务页面；业务页面统一在 `remote/*` 内实现。

### 2.2 子包内部结构（基础模板）

```
src/
├── main.tsx            # 仅 import('./bootstrap')，为 MF 让出异步入口
├── bootstrap.tsx       # ReactDOM.createRoot + <App />
├── App.tsx             # 独立运行时的路由/主题容器（仅 dev/preview 用）
├── <Name>App.tsx       # MF exposes 的入口组件（仅在 remote/* 出现）
├── index.css           # Tailwind 入口 + 全局样式
├── api/                # 按后端服务分文件，如 auth.ts / federation.ts
├── components/         # 子包内跨页面复用的组件
├── config/             # 应用级配置（仅 host 使用）
├── constants/          # 子包内复用的常量
├── contexts/           # 应用级 React 上下文，可就近导出消费 hook
├── features/           # 多页面或嵌入入口复用的完整业务功能
├── hooks/              # 通用 hooks，命名以 use 开头
├── pages/<PageName>/index.tsx  # 页面目录化，私有组件同目录
├── remote/             # 远程模块加载器（仅 host 使用）
├── router/             # 路由（仅 host 使用）
├── styles/             # 公共样式、主题、表单布局配置
├── types/              # 全局/接口类型定义（.d.ts）
├── utils/              # 公共工具与适配函数
└── vite-env.d.ts
```

**强约束**：

- `main.tsx` 必须是异步壳：
  ```ts
  import('@/bootstrap');
  ```
  否则顶层同步依赖会导致 MF remote 加载失败。
- 每个子应用的 MF 入口文件命名为 `<Name>App.tsx`（如 `SystemApp.tsx`、`LoginApp.tsx`），路径别名 `@/` 指向 `src`。
- 页面文件统一放在 `pages/<PageName>/index.tsx`，❌ `pages/UserManagement.tsx` 扁平文件。

### 2.3 页面、功能与公共代码归属

- `pages/<PageName>/`：菜单或路由对应的页面，目录使用 PascalCase。页面专属的组件、hooks、模型、类型和样式随页面就近组织，业务入口从 pages 懒加载。
- `features/<feature-name>/`：多个页面或嵌入入口复用的业务功能，目录使用 kebab-case。页面通过参数和组合复用功能，避免复制整份实现；例如 board 的四类资源管理和嵌入看板渲染。
- 子包内跨页面复用的组件、hooks、工具、样式、常量、上下文和类型，直接放在 `src` 下对应的 `components`、`hooks`、`utils`、`styles`、`constants`、`contexts`、`types`，不再增加 `shared` 层。目录按需创建，不保留空目录。
- 依赖方向为 pages → features/公共代码、features → 公共代码；公共代码不得反向引用 pages 或 features，features 不反向依赖 pages。跨页面复用的组件或 hook 可以包含业务含义，不必为单个组件另建 feature。
- 单个页面或 feature 专用的实现随使用方组织：组件放在其 `components` 内，其余私有文件优先放在所属目录根层；已有页面私有 hooks 等分类可以保留。复用范围按页面或功能判断，同一页面内多个文件引用不等于跨页面复用。
- 公共样式、主题和 `formLayout` 放在 `styles`，样式相关的 hook 放在 `hooks`；迁移时保持样式的作用范围和加载顺序。
- 无适配逻辑的纯转发文件直接删除，调用方引用原始模块；带错误处理、返回值适配、保存校验或业务类型绑定的封装保留。迁移同时更新测试、mock 和预览配置，不保留旧路径转发或兼容别名。
- 仓库根目录的 `share/*` 是独立共享工程，与子包内部目录分类不同；跨子包共享继续遵循 comm / data 与 Module Federation 的边界。

## 三、Module Federation 规范

### 3.1 命名与产物

| 项 | 约定 | 示例 |
|----|------|------|
| Remote name | 全小写、与 `app_code` 一致 | `system`、`login`、`comm` |
| exposes | `./<name>` 暴露一个主入口 | `./system` → `./src/SystemApp.tsx` |
| filename | `<name>.js` | `system.js` |
| entryGlobalName | 与 name 相同 | `system` |
| shareScope | 统一 `default` | — |
| shareStrategy | 统一 `loaded-first` | 避免启动时预加载全部 remote |

- 业务 remote 仅暴露应用主入口；`share/data` 按数据集编辑、查询控件及三类嵌入预览分别暴露能力入口，页面复用的组件、上下文与辅助接口从对应入口命名导出。

### 3.2 shared 声明模板

所有子包保持一致：

```ts
shared: {
  react:              { singleton: true },
  'react-dom':        { singleton: true },
  'react-router-dom': { singleton: true },
  antd:               { singleton: true },
  axios:              { singleton: true },
}
```

### 3.3 静态 vs 动态 remote

- **构建期已知 remote**（`comm`、`data`、`login`）：写入 `vite.config.ts` 的 `remotes` 字段。
- **动态业务 remote**（后端下发的 `app_code`）：仅在运行时通过 `@module-federation/runtime` 的 `registerRemotes` 注册，入口统一走 `host/src/config/remotes.ts` + `loadRemoteModule.ts`，❌ 业务代码直接 `registerRemotes`。

### 3.4 环境变量

- 开发：`VITE_<APP>_ENTRY` 指向 `http://localhost:<port>/<app>.js`。
- 生产：入口统一相对路径 `<appCode>/<appCode>.js`，由部署方案决定 `base`。
- `VITE_*_PORT` 仅在 `.env.development` 中出现，`.env.production` 不出现端口。
- 新增子应用后：`host/.env.development` 添加 `VITE_<APP>_ENTRY`。

## 四、路由与鉴权

- 路由集中在 `host/src/router/index.tsx`，业务子应用通过 `<Route path="/<app>/*" element={<RemotePage />} />` 挂载。
- 子应用内部使用 **相对路由**（`<Route path="user" />`），❌ 硬编码 `/<app>/user`。
- 未匹配路径统一使用 `comm/theme` 的 `NotFoundRedirect`。
- 鉴权走 `host/src/router` 的 `RequireAuth`：只读 `sessionStorage`，token key 常量为 `session_id`（见 `comm/session` 的 `TOKEN_STORAGE_KEY`）。会话读写统一使用 `comm/session` 暴露的 `getSessionId / setSessionId / clearSessionId`，❌ 直接调用 `sessionStorage`。
- 页面跳转统一使用 `useNavigate()`，❌ `window.location.href = '/xxx'`

### 模块上下文（moduleId）

- 侧边栏路径由 `comm/moduleContext#buildModulePath` 生成，格式 `/<app>/<entry>?moduleId=<id>`。
- 页面读取当前 moduleId 统一使用 `useCurrentModuleId()`，❌ 手动解析 `location.search`。

## 五、HTTP 请求规范

**唯一入口**：`import { request } from 'comm/request'`。

### 5.1 API 层组织

- 按后端服务（proto 文件）分文件，如 `api/auth.ts`、`api/federation.ts`、`api/user.ts`。
- 参数与返回值标注类型；返回值类型放 `types/<domain>.d.ts`。
- URL 路径**不以 `/` 开头**（`baseURL: '/api'` 已包含），例：
  ```ts
  request.post<GetSessionInfoRes>('auth/GetSessionInfo', params);
  ```

### 5.2 响应处理

- 后端统一响应结构 `{ code, message, hint? }`，`code === 0 | 200` 视为成功。
- 非成功响应由 `comm/request` 拦截器统一 `message.error`，业务代码**不重复弹错**。
- 需要拿到原始 body（非标准响应）时使用 `{ rawResponse: true }` 配置，❌ 绕过 axios 实例。

## 六、状态与数据流


- 跨子应用共享状态统一：
  1. 通过 `comm/session` 读写 `sessionStorage`（会话）；
  2. 通过 `comm/eventBus` 发布订阅（低频跨窗口事件）；`session_id` 变更用 `onSessionIdChange` 订阅。
- 存放业务状态；session 相关统一走 `getSessionId / setSessionId / clearSessionId` ❌ 直接读写 `window.localStorage`

## 七、组件与 UI

### 7.1 组件规范

- 组件内部 ❌ 使用 `App.useApp()` 之外的方式获取 `message`；`message` 统一从 `App.useApp()` 取，❌ `import { message } from 'antd'`（会脱离主题、脱离 message setter）。

### 7.2 弹窗按钮规则

对话框（Modal / Drawer 等）底部按钮语义统一，文案与行为一一对应，❌ 混用（如「确定」只保存不关闭、「保存」顺带关闭）。

| 按钮 | 行为 | 说明 |
|------|------|------|
| **确定** | 保存当前内容，并关闭对话框 | 提交 + 关闭；失败时不关闭 |
| **取消** | 不保存当前内容，并关闭对话框 | 丢弃本次编辑 |
| **关闭** | 关闭对话框 | 可选：存在未保存内容时，提示是否保存 |
| **保存** | 保存当前编辑内容，**不关闭**对话框 | 仅落盘，用户继续编辑 |

### 7.3 样式

- Host 与独立入口通过 `comm/theme` 的 `AppThemeProvider` 统一配置主题；默认 `mode="system"` 跟随系统，Host 的 `primaryColor` 使用后端品牌配置。每个文档仅在整页入口使用 `AppThemeRoot` 同步根变量、`data-theme` 与 `color-scheme`。
- 业务组件通过 `useAppTheme().resolvedMode` 读取当前作用域的明暗状态；局部覆盖使用 `AppThemeScope`。`usePrefersDarkMode()` 仅保留为读取系统偏好的兼容 API，不能用背景色字符串推断主题。局部作用域不能写 `documentElement`。
- metric、board、report 的管理规格与 CSS 变量统一来自 `data/theme`；`DataThemeScope` 或 `useDataThemeStyle()` 使用当前 AntD token。Modal 的 `style`、Drawer 的 `rootStyle` 需要独立注入变量，因为 CSS 继承不会随 React Context 跨越 Portal。大屏弹窗恢复宿主时，同时恢复主题配置与明暗状态。
- 页面 shell（`html/body/#root`、视口变量、基础字体与链接/列表重置）统一在 `share/comm/src/styles/shell.css`。它是构建时共用源码，仅各独立运行入口的 `bootstrap.tsx` 使用相对路径导入；不要从 `comm/theme`、业务组件、联邦 expose 或 CSS 包装文件引入。
- login 与 visit 演示应用的独立入口另导入 `shell-scroll.css` 保留页面滚动。嵌入 host 时不加载这两个 shell 文件；host 的短屏 Modal 规则仍由 host 管理。
- 各应用 `index.css` 只保留 Tailwind utilities/theme、图标和作用域业务规则。业务 App、widget expose 仍需引入它，不能因剥离 shell 而删除 utility 样式。visit 消费方现有的 `@source "../../../share/visit/src"` 仍需保留。
- 普通界面优先使用 `comm/theme` 导出的 `appThemeVars` 语义变量；新增引用先确认变量已定义。局部主题可以声明作用域变量；数据大屏/预览主题不必强行映射为普通页面主题。Tailwind CSS 变量使用 `bg-(--app-theme-bg-container)` 或 `bg-[var(--app-theme-bg-container)]`，不要写 `bg-[--app-theme-bg-container]`。
- 提交主题相关变更前运行根目录 `npm run theme:check` 与 `npm run theme:test`。检查覆盖业务源码中的变量定义/引用、shell 导入边界及文档 reset；排除第三方 assets、生成声明和构建产物。静态检查不证明变量继承范围、颜色对比度或 CSS 分包正确，仍需验证嵌入态与独立态的明暗主题及弹窗。

## 八、类型约定

- 接口类型放在 `src/types/<domain>.d.ts`，与后端 proto 字段命名保持一致
- `interface` 用于对象契约，`type` 用于联合/交叉/映射；不混用。

---

## 十、错误与日志

- 用户可感错误：由 `comm/request` 拦截器统一 `message.error`。
- 业务边界错误：`try/catch` 后调用 `App.useApp()` 拿到的 `message.error`，
- 未捕获错误：不引入 ErrorBoundary 前，禁止让远程模块加载失败时白屏（走 `RemoteModuleLoader`）。
